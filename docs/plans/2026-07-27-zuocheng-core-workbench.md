## 产品决策

- 根路径直接进入做成■的真实任务工作台，不进入登录页、身份门户或“本地模式”说明页。
- 登录和注册只作为页头右上角的标准账号入口；用户主动点击后才显示认证界面。
- 匿名、本地持久化、同步、零固定成本和自带资源都是实现策略，不作为首屏卖点或教学文案。
- 页面丰富度来自真实任务交互：材料、交付定义、证据、结构、核验和导出；不得用口号、说明卡和工程术语填充界面。
- 暂未实现的能力必须显示为不可执行或不出现，不能用 Toast、静态样例或假状态冒充成功。

## 核心用户旅程

1. 用户打开根路径，看到项目页头、当前任务和六阶段工作区。
2. 用户可直接创建任务，并填写任务名称、听众、截止时间、页面或字数、演讲时长、输出格式、评分标准、语气、必须包含和禁止包含。
3. 用户上传真实文件；系统校验文件名、类型和大小，计算内容哈希，显示上传与解析进度，并对失败提供原因、重试和替换。
4. 系统保留 PDF 页码及原文锚点；用户从真实解析结果中选择证据，补充类型、备注和引用格式。
5. 用户创建、比较、排序、锁定、复制和删除结构节点；每个节点必须绑定证据。
6. 用户编辑逐页初稿，运行真实规则核验，并修复无来源主张、缺失引用、时间超限和评分标准缺口。
7. 用户生成并下载真实 PPTX、PDF、DOCX、Markdown、讲稿、来源索引、任务定义卡、核验记录和完整项目包；成功必须以可下载文件及内容校验为证据。
8. 登录后可同步、协作和跨设备继续；登录不是匿名核心流程的前置条件。

## 实施任务

### WB-01 前台入口与信息架构

- 先写测试，证明根路径出现核心工作台及六阶段导航。
- 先写测试，证明登录和注册只在页头右上角，且未点击时认证表单不在 DOM 中。
- 删除“先开始，账号稍后再说”“本地起步”“按需同步”等内部策略文案。
- 把身份管理页面移到用户主动打开的账号入口之下。

### WB-02 本地项目领域模型与持久化

- 定义 Project、TaskDefinition、SourceFile、SourceChunk、EvidenceCard、Outline、Artifact 和 VerificationResult 的稳定版本化模型。
- 使用 IndexedDB 保存真实任务、文件 Blob、解析结果和编辑历史；刷新后恢复。
- 为后续登录迁移保留明确的导出/导入边界，但不在前台宣传“本地模式”。

### WB-03 真实 PDF 上传与解析

- 上传前校验文件名、MIME、扩展名和大小。
- 使用 SHA-256 识别重复文件。
- 在浏览器中解析真实 PDF 文本和页码；25 页 PDF 必须形成 25 个可追溯页面块。
- 解析错误必须可重试或替换。

### WB-04 任务定义、证据和结构

- 任务定义字段全部真实保存并生成验收清单。
- 证据只能来自真实 SourceChunk，保留文件、页码、原文、类型、备注和引用。
- 结构节点支持排序、锁定、复制、删除、证据绑定和方案比较。
- 没有来源的内容不能标为已核验。

### WB-05 初稿与核验

- 每页保存结论、证据、图表建议、视觉说明、引用、讲述备注和预计时长。
- 核验覆盖数字一致性、引用存在性、相关/因果、无证据主张、重复、时间、评分标准和敏感内容。
- 用户锁定的内容不会被局部重生成覆盖。

### WB-06 真实导出

- 生成真实且可打开的 PPTX、PDF、DOCX 和 Markdown。
- 同步生成讲稿、来源索引、任务定义卡、核验记录和完整项目包。
- 测试必须检查文件签名、内部条目或解析后的内容，不能只检查下载事件。

### WB-07 账号辅助入口

- 登录、注册、Passkey、OAuth、恢复和安全中心保留真实后端能力。
- 只有用户主动点击账号入口或发起同步/协作时才展示。
- 匿名任务在认证前后不得丢失；迁移与冲突处理在 ZC-04 以真实双端证据验收。

### WB-08 用户体验与发布证据

- 375、768、1024、1440 四视口无横向溢出。
- 键盘可完成核心旅程，焦点、错误、进度和状态符合 WCAG 2.2 AA。
- 以真实 25 页 PDF 完成“3 页汇报、6 条证据、结构、修改、核验、PPTX/PDF”浏览器 E2E。
- 通过 Node 24.14.0 全仓验证后再提交部署证据。
